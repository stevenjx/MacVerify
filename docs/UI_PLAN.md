# MacVerify 界面规划与美化流程 / UI Plan

> 目标不是「变好看」，而是让一台二手 Mac 的真实状况**在 10 秒内被看懂，并且每个数字都能被核对**。
> 所有改动不得触碰采集与判定逻辑；界面只能改变呈现方式，不能改写事实。

---

## 一、现状盘点（基于代码实测，不是感觉）

| 项目 | 现状 |
| --- | --- |
| 视图文件 | 16 个，3312 行 |
| 最大的三个 | `OverviewView` 415 行、`Components` 364 行、`InputTestView` 363 行 |
| 字号种类 | 16 种（9 / 9.5 / 10 / 10.5 / 11 / 11.5 / 12 / 13 / 14 / 15 / 18 / 19 / 20 / 22 / 24 / 26 / 38） |
| 最常用字号 | 11pt（52 处）、10pt（36 处）、9pt（13 处）——正文低于 macOS 常规正文 13pt |
| 状态色映射 | 分散在 3 处：`BadgeLevel.color`、`OverviewView.color(for:)`、`LoadTestView.color(for:)` |
| 状态色取值 | 直接用系统 `.green` / `.orange` / `.red`，浅色模式下小字对比度不足 |
| 设计令牌 | 无。间距、圆角、卡片内边距都是就地写死的数字 |
| 页面数量 | 13 页，侧栏分 4 组 |
| 本地化 | 全量 `T()`，中英双语 |
| 主题 | `ThemeStore` 支持跟随系统 / 浅色 / 深色 |

三个直接后果：

1. **数字太小**：大量 10–11pt 正文，表格里再叠一层 9pt 说明。验机场景常在光线差的摊位上看屏幕。
2. **状态色不统一**：同一个「不一致」在三个文件里各写一遍，改一处会漏两处。
3. **概览页过载**：415 行里同时塞了设备卡、一致性卡片、原装性卡片、检查项网格，结论被明细淹没。

## 二、设计原则（先定规则，再谈美化）

1. **结论先行**：每页顶部给出「这台机器整体如何」，明细往下滚。不做需要用户自己拼结论的界面。
2. **数字比标签重**：数值用等宽字体、字重更高；标签弱化。人眼先抓数值。
3. **状态色只表达状态**：绿色只用于「核对通过」，绝不用于装饰；「不可用」必须与「正常」在视觉上可区分但不刺眼（用中性灰 + 减号图标，不用绿色）。
4. **不改事实**：任何美化都不得把 `unavailable` 渲染成空白、破折号伪装成 0，或隐藏低分项。
5. **一屏一结论**：最小窗口 1000×680 下，每页首屏必须能看到该页的核心结论。
6. **可核对**：每个结论旁保留数据来源入口（现在报告里的 source 链接做法是对的，界面沿用）。

## 三、设计令牌（新增 `Core/DesignTokens.swift`）

把散落的魔法数字集中成一套令牌，全部界面只引用令牌。

### 字号（6 档，替代现在 16 种）

| 令牌 | 值 | 用途 |
| --- | --- | --- |
| `Font.display` | 26pt semibold | 页面主标题（现 20pt 偏小） |
| `Font.title` | 15pt semibold | 卡片标题 / 分组标题 |
| `Font.body` | 13pt regular | 正文、列表标签（对齐 macOS 正文） |
| `Font.value` | 13pt medium + monospacedDigit | 数值列 |
| `Font.caption` | 11pt regular | 次要说明、单位 |
| `Font.mono` | 11pt monospaced | 序列号、ID、指纹、路径 |

> 现状 9pt / 10pt 全部并入 `caption`，不再出现 9pt 以下文字。

### 间距（4 的倍数）

`Space.xs = 4`、`sm = 8`、`md = 12`、`lg = 16`、`xl = 24`、`xxl = 32`。
卡片内边距统一 `lg`（现为 16，保持不变），卡片间距 `lg`，页面边距 `xl`。

### 圆角与描边

`Radius.card = 10`（现 8–10 混用）、`Radius.control = 6`。
卡片用 1px 分隔线代替投影，深色模式下去掉描边改为 1px 高亮边。

### 状态色（浅色 / 深色各一套，满足 4.5:1）

| 语义 | 浅色 | 深色 | 备注 |
| --- | --- | --- | --- |
| ok | `#1B7F3B` | `#4ADE80` | 不用系统 `.green`（浅色下小字对比不足） |
| warning | `#A85B00` | `#FBBF24` | |
| critical | `#B42318` | `#F87171` | |
| neutral / unavailable | `#6B7280` | `#9CA3AF` | 「不可用」固定用此色 + 减号图标 |

状态色只在三处出现：徽章、数值文字、卡片左侧 3px 竖条。其余一律用主/次文字色。

## 四、信息架构调整

侧栏从 4 组 13 页保持不变（刚新增的「外设」与「两次对比」已就位），只调整**页面职责**：

| 页面 | 职责（改造后） | 首屏必须有 |
| --- | --- | --- |
| 概览 | 结论页。顶部一张「总判决卡」，下面三类分区：身份 / 风险 / 使用痕迹 | 总判决 + 未通过项数 |
| 设备信息 | 身份与配置，只读展示 | 机型、芯片、内存、容量四行 |
| 安全与合规 | 布尔状态清单 | 未开启项数量 |
| 显示屏 | 面板身份 + 纯色检查 | 分辨率、面板序列号 |
| 存储 | 容量、SMART 寿命、实测读写 | 寿命百分比 |
| 性能测试 | CPU/GPU 实测 | 单核/多核成绩 |
| 键盘与触控板 | 覆盖进度 | 已覆盖键数 / 总数 |
| 电池 | 健康度、循环、内阻 | 健康度百分比 |
| 电池负载测试 | 放电曲线与判定 | 判定结论 |
| 供电 | 适配器与功率 | 适配器功率 |
| 外设 | 无线 / 音频 / 总线 | Wi-Fi 与蓝牙芯片、雷雳口数 |
| 两次对比 | 差异表 | 差异项数 |
| 关于 | 版本、导出、指纹 | 报告指纹 |

**概览页改造要点**（415 行是最大技术债）：

- 拆成 4 个子视图文件：`OverviewHeader`、`OverviewRisks`、`OverviewIdentity`、`OverviewUsage`，`OverviewView` 只做组装。
- 总判决卡：左侧色条 + 一句话结论（「未发现需要关注的问题」/「2 项不一致」），右侧放「导出报告」「去对比」两个动作。
- 检查项网格：现在是一堆同权重的方块，改为**按状态排序**（critical → warning → ok → unavailable），异常项永远在最上面。

## 五、逐页改造清单

### P0（先做，收益最大）

1. **令牌化**：新增 `DesignTokens.swift`，替换全部 `font(.system(size:))` 与状态色；3 处状态色映射合并为 1 处。
   *验收*：全项目 `\.font\(\.system\(size:` 出现次数 ≤ 令牌定义处；`BadgeLevel.color` 是唯一状态色来源。
2. **正文提到 13pt、说明 11pt**：表格行高从 ~22 提到 26，列表可读性直接改善。
   *验收*：9pt/10pt 字号计数为 0。
3. **概览页拆分 + 结论前置**：415 行拆成 5 个文件，总判决卡置顶。
   *验收*：`OverviewView.swift` ≤ 120 行；1000×680 下首屏可见总判决与异常项数。
4. **深色模式校正**：状态色换令牌值，卡片描边在深色下改为高亮边。
   *验收*：浅/深两套截图，状态文字对比度 ≥ 4.5:1。

### P1（体验提升）

5. **数值列对齐**：所有数值用 `monospacedDigit`，同类数值右对齐或小数位对齐；容量、百分比、温度统一单位写法。
6. **空状态与不可用状态区分**：`unavailable` 用灰 + 减号；「确实没有」（如 USB 未连接）用灰 + 「无」。两者文案不同，颜色相同但图标不同。
7. **外设页与对比页补齐分组标题与图标**，与整体风格一致；对比页差异行改为左侧色条 + 新旧值上下排，窄窗口不挤。
8. **侧栏分组图标与选中态**：选中态从纯色块改为「色块 + 左侧 2px 高亮」，减少大面积饱和色。

### P2（打磨）

9. **图表**：电池负载曲线、CPU/GPU 基准横向条，用 Swift Charts（macOS 13+）或轻量自绘；当前系统要求 macOS 12，需保留降级路径。
10. **首次启动引导**：一页说明「这个工具看什么、不看什么」，降低误读。
11. **键盘导航与 VoiceOver 标签**：所有 StatusBadge 加 `accessibilityLabel`。

## 六、执行流程（每一步都可验证）

```
1. 基线截图
   固定 1000×680 与 1440×900 两档，浅色/深色各一套，中/英各一套 → docs/screenshots/before/
2. 建设计令牌
   新增 DesignTokens.swift → 编译 → grep 校验字号/颜色来源收敛
3. 改组件层（Components.swift）
   先改 Card / InfoRow / StatusBadge / NoticeBar / Button，因为所有页面都依赖它
4. 逐页替换
   每改完一页立刻跑：xcodebuild + 13 页冒烟 + 报告 diff
5. 回归数据层
   MACVERIFY_DUMP_REPORT 与改版前对比，字段值必须完全一致（只允许排版变化）
6. 截图对比
   after/ 与 before/ 同尺寸同主题逐张比对，写进 PR 说明
7. 深色 + 英文 + 窄窗口三组交叉验证
```

**硬性回归门槛**（每页改完都要过）：

- `xcodebuild` 零 error、零新增 warning
- 13 个页面 `MACVERIFY_PAGE` 冒烟无崩溃
- 报告 JSON 与改版前 `diff` 为空（除版本号、时间、指纹无关字段）
- 中英文切换后无截断、无重叠（目视 + 截图）

## 七、验收标准（可测量，不靠主观）

| 指标 | 目标 |
| --- | --- |
| 字号种类 | ≤ 6 种 |
| 小于 11pt 的文字 | 0 处 |
| 状态色定义位置 | 1 处 |
| `OverviewView.swift` 行数 | ≤ 120 |
| 状态文字对比度 | ≥ 4.5:1（浅色与深色均满足） |
| 首屏信息 | 每页 1000×680 下可见该页结论 |
| 中英切换 | 无截断、无控件位移 |
| 报告数据 | 与改版前逐字段一致 |

## 八、明确不做

| 不做 | 原因 |
| --- | --- |
| 自定义皮肤 / 多套主题 | 验机工具不需要个性化，反而增加维护面 |
| 大面积渐变、玻璃拟态、毛玻璃 | 与「读数可信」的定位冲突，且在弱光环境下降低可读性 |
| 入场动画、数字滚动动画 | 会拖慢「快速看结论」这个核心动作 |
| 用颜色表达「好/坏」以外的含义 | 状态色语义必须单一，否则读者会误判 |
| 改采集逻辑来迁就排版 | 界面服从数据，不能反过来 |
